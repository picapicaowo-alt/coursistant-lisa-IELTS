## 已修复的前端问题

| 编号 | 原因和结果 | 验证 |
| --- | --- | --- |
| F22 | 刷新 token 与重放业务请求共用一个 `catch`。刷新成功后业务请求的 403、409、503 被当成刷新失败，统一改写 401 并退出。现在只捕获刷新失败，重放结果保留真实状态码；刷新后的核心请求仍为 401 时才按不可恢复会话处理。 | 真实 Axios 拦截器回归分别验证三种状态码、token 保留与不触发退出；先复现失败，再验证修复。 |
| F23 | API 实例缓存旧 bearer，其他标签页退出／切换账号后仍可能沿用；旧请求和延迟刷新也可能覆盖新身份。现在每次请求读取当前凭据，核对请求身份，忽略旧身份的延迟响应与刷新成功／失败，同步其他标签页身份并清除旧 Query 缓存、重建受保护页面。 | 并发刷新、旧响应、延迟刷新成功／失败、跨标签页 Settings 草稿隔离及双页退出均通过。 |
| F24 | 教师课程作业区链接到仅允许 Student 查看个人成绩的页面。移除该无效入口，保留作业明细与批改入口。 | 教师页面不再有学生个人成绩链接，学生已发布作业成绩和教师批改待办仍可进入。 |

F22 属于前端错误分类问题；它不能证明某个原始 403、409 或 503 本身是后端故障。403 的权限、409 的业务冲突和 503 的具体原因仍应按实际接口响应判断。

本轮修改的界面文案均通过共享 i18n 增补英文、简体和繁体资源。全站其他既有语言迁移仍未完成，此处只证明本轮增量的资源一致性。
