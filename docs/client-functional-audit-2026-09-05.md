## 新增修复

| 编号 | 触发及原行为 | 修复结果与证据 |
| --- | --- | --- |
| F25 | 已有一个暂存作业文件，再上传新文件时仍能点击提交；提交期间仍能删除文件或继续上传 | 跟踪上传／删除及暂存列表回读；完成前禁用提交。正式提交期间锁定文件操作。失败回读有明确提示和只读重试，不会把旧文件列表用于提交。两项并发回归先失败，修复后通过。 |
| F26 | 提交失败后换成另一组文件，仍沿用弹窗初始化时生成的 Idempotency-Key | 使用既有幂等工具，以课程、作业、排序后的文件 ID 集合作为请求身份；同请求重试复用 key，换文件生成新 key。回归核对实际传给 service 的 body 和 header 参数。 |
| F27 | 后端已接受作业，但后续状态读取失败时，弹窗仍可能说提交失败并再次发送提交请求 | 记住本次正式提交已经成功；之后重试只读取提交状态，文件操作保持锁定。父级 refetch 显式抛出读取失败，避免吞掉错误。回归确认两次状态读取只产生一次提交写入。 |
| F28 | 阅读图题媒体 URL 使用数组位置，而合同路径要求 passageSeq / sortOrder；非连续顺序时请求错误地址，整张试卷打不开 | 解析并保留题组 sortOrder；使用真实段落 seq 和题组 sortOrder。浏览器以 seq=3、sortOrder=7 的试卷复现，再验证请求 `/reading/passages/3/questions/7/image` 和图片／答题框呈现。 |
| F29 | 答题页查询超过五分钟缓存期限后，窗口恢复焦点或网络重连触发重读；503 会切到错误页并卸载未提交写作内容，成功媒体重读也会替换 Blob URL | 活跃答题会话禁止后台焦点／重连重载，明确重试仍保留。切换考试／科目时按身份重建答题工作区。浏览器推进六分钟并触发重连，确认原文保留且没有额外读取。此修复不等于刷新浏览器后的草稿恢复。 |
| F30 | 多个模考媒体并行加载时，部分成功已经生成 Blob URL，后续请求失败或离开页面却没有组件负责回收这些 URL | 全部媒体读取成功且查询未取消后才统一生成 URL；保留已挂载页面的正常回收。浏览器验证部分失败不生成孤立 URL，重试后正常打开写作页。 |
| F31 | 学生尚无正式提交时，上传成功后仍提示“至少选择一个文件”；旧 assignment.stagedFileCount=0 导致跳过暂存文件读取 | 无正式提交的正常 404 分支始终读取实际暂存列表，去掉过期计数条件。浏览器先复现文件可见却无法提交，再用三语验证首次上传→提交→状态失败→只读重试→刷新。 |

1. 本轮真实测试账号及其角色／课程关联。浏览器只有公开登录页；已请求账号或用户登录后交接，未伪造受保护会话。

3. 对以前提出的外部事项做同身份、同资源、正确版本参数的关闭验收。不能沿用旧故障，也不能仅凭前端适配判断后端已修复。
4. 明确 AI、消息／邮件实际投递及需要真人参与的写操作范围；本轮没有向他人发送消息，没有改动 Parent–Student 关系。
5. 候选合并／部署后，再完成真实登录、刷新、关键角色流程及退出。当前候选尚未发布到 Production。
