## Contract and interaction constraints

- `docs/api/mockexam.openapi.yaml` defines `StudentMockExamSummaryDto` with `attemptStatus`, reading/listening correct and total counts, `writingScore`, and `writingGradeStatus`. These already support richer cards. Do not invent duration, progress denominators, Speaking support, or aggregate bands. The existing IELTS runner is already outside `Layout`; its passage/audio interactions differ materially from the question-rail frame and must remain functional through any restyling.
- **Correct a stale source assumption:** `AssignmentSummary` and `AssignmentsCard` comments say assignments lack Lecture/learning-category information. The current `docs/api/assignment.openapi.yaml` list/summary descriptions explicitly include Lecture display, `learningType`, `submissionStatus`, `studentListGroup`, and released score/feedback; creation requires `weekId` and `learningType`. The summary success schema remains generic, so confirm its projection rather than invent nested fields, but do not classify these concepts as categorically absent from the contract.
- Assignment completion is not lesson playback completion. Free-text baseline is not a numeric level; missing learning-report metrics, study minutes, enrollment dates and strength classifications cannot be fabricated to fill Figma.
- `AdvisorTaskResponse.submissionFileObjectKey` exists, but an object key alone is not an authorized browser download URL. The task-linked quiz in `430:2779` and the task attachment in `464:3172` need their own documented delivery/destination behavior before being presented as working controls. `819:9475` belongs to the Advisor All exam list and requires observer question/answer read/edit capabilities; it is not a task-linked quiz destination.
- Keep supported structured names, tenant context and verification fields in registration. Do not substitute an invitation-code or OAuth contract. Course note persistence, parent-specific Advisor messaging, AI history/share/image/research, and calendar participants remain constrained by consumed contracts; the [handoff](../../advisor-figma-backend-handoff.md) records these differences.
- A route/layout change does not grant permission. Preserve Student/Advisor/Parent/Instructor/TA and Tenant/System Admin boundaries, documented request fields, versions and course-local time semantics.

## Concrete acceptance criteria and existing test limits

1. At 1440, 1920 and 2560px, verify major panel bounds against the shared content edges and assigned spans, including zero/one/many records. At 320, 390 and 768px verify readable labels, reachable controls, useful stacking, no document overflow and no accidental centered narrow grids. Inspect screenshots, not geometry alone.
2. Exercise navigation for every role: each workflow reaches its own destination, selected navigation is correct, and full operational sections are absent from Dashboard. Dashboard and My Courses must agree for an enrolled student with zero upcoming assignments.
3. Refetch must retain applied directory filters, make a new read, expose loading/completion or failure, and avoid a detached toolbar row. Intake creation must open a named modal, keep the page stable, trap/restore focus, close via supported dismissal, preserve validation, and submit exactly once.
4. Course detail/reader must have the intended focused shell and working Back, next item and Discussion. AI empty-state spacing must stay bounded; a populated thread must scroll without hiding the composer. Messages must retain send/retry/pagination/attachments without duplicate card chrome.
5. Verify released/unreleased and started/completed exam fixtures; accurate scores, totals and status; no invented bands. Verify Settings computed colors/focus, field validation and save feedback. Verify Calendar today, event overlap and versioned create/edit using local seconds/timezone. Verify progressive auth retains every required request field and error state.
6. For profile, course assignment and exam assignment modals, exercise pending, failure, retry, cancel/Escape and successful close; the result/error must be visible in the active surface and focus must return. For task links, use two tasks in one checkpoint and assert each selected identity; include a pending request beyond the first ten records.
7. Test populated AI threads separately from the empty welcome: long assistant text, code/list formatting, response copy feedback, scroll position and a reachable latest-message action. Test course-reader sidecar closure without losing the selected material. For exam completion, preserve unsaved answers on failed submission and show completion only after success.
8. Record a fresh **application** screenshot and interaction result for each of the 69 matrix states, or explicitly record an unresolved contract dependency. Reuse a route only when its distinct modal/filter/error/success state is actually exercised. Mark application states unverified until this occurs; fresh Figma-reference coverage does not establish implementation parity.
